- [ ] **Modless client freezes at 4:00 — PARTIALLY RUN 2026-08-23, AND THE MECHANISM IS NOW READ OFF SOURCE RATHER THAN INFERRED.** Mathew played a real two-machine session, host with the mod, **client without it**, and reported *"time seemed to sync fine."* **That is consistent with the prediction, not a refutation of it, and the difference is one branch.** `RpcLogic___PassMinute_Client(int oldTime)` is not an unconditional assignment: it opens with `if (!this.ShouldMinutePass())`, and only the ELSE branch does `this.CurrentTime = oldTime`. `ShouldMinutePass()` is `CurrentTime != 400 && (!IsCurrentTimeWithinRange(400, 600) || IS_TUTORIAL)`, evaluated against **the client's own clock**. So outside 04:00-06:00 a modless client tracks the host exactly — which is what Mathew saw — and at 04:00 the assignment is skipped and its clock stops. **The session almost certainly never crossed 04:00. The check is still open and the only minute that matters is 04:00.**
  **AND THERE IS A SECOND, NEWER FINDING THAT NOBODY WAS LOOKING FOR: the mod may be what STRANDS such a client.** Vanilla's escape hatch is `SkipForwardToTime`, whose body ignores its own argument and calls `OnTimeSkip_Client(CurrentTime, 700)` — an `[ObserversRpc]` whose logic calls `SetTime(newTime)` with **no `ShouldMinutePass` check at all**. That RPC is the one thing that can unstick a client frozen at 04:00. **But `Patch_TimeManager_SkipForwardToTime.Prefix` returns false whenever `CurrentTime >= 700`**, which suppresses the broadcast. Whether it fires is therefore a **race against the host's clock**: the mod triggers `StartSleep` at `CurrentTime > 658`, so the host is normally still at 0659 when sleep end lands and the skip goes out — but the silent-sleep routine yields a frame and then waits on the save, and **at a high `DaySpeedMultiplier` an in-game minute is a fraction of a second**, so the host will be past 0700 by then and the skip is suppressed. **A modless client would then never recover.** Not a defect in a supported configuration — all three player-facing copies already say everyone needs the mod — but it is now understood, and it should be checked deliberately rather than discovered by a player. **Test: host with the mod at `DaySpeedMultiplier=10`+, modless client, play through 04:00.**
